# 技术栈地图：实现证据、学习优先级与验收

[七节课程](README.md) · [面试追问练习](INTERVIEW.md) · [深度学习方法](STUDY-METHOD.md)

本地图按训练脚手架、扩散微调与研究评测项目整理，供学习和岗位准备使用。它是能力规划，不是全国岗位需求排名。**代码里有实现、在指定环境验证过、学习者能独立解释与修改，是三种不同证据。** 以下不替学习者认定“熟练”；掌握程度由练习与演示检查。

## 1. 当前最值得建立的能力组合

Python 工程组织 → PyTorch 训练正确性 → 数据与评测 → 可复现与性能测量 → Diffusion/LoRA → 可靠推理服务。Linux、Git、SQL 和测试贯穿其中。这个顺序由现有项目与下一阶段扩散项目需求确定。

训练/模型评测路线强调数据切分、优化与状态恢复；AIGC 路线进一步强调生成模型机制、微调数据、质量评测与服务隔离；具身路线需要另外增加时序数据、动作/控制、闭环评测，不能仅由文生图或小型世界模型项目推导已经掌握机器人栈。

## 2. 按证据整理技能，而不是列库名

| 能力 | 已有证据 | 尚不能由它推出 | 下一步验收 |
|---|---|---|---|
| Python 工程 | dataclass、argparse、Path、context manager、模块分工与 pytest | 任意 Python 问题都能独立解决 | 不看模板写配置覆盖与异常流程，说明对象状态与副作用 |
| PyTorch 训练 | [train.py](../../src/train.py) 有累积、裁剪、优化器和调度；参数等价测试覆盖尾批 | 所有 loss reduction、BN/Dropout 组合都严格等价 | 从公式推导当前分母；设计 token/类别权重场景的正确分母 |
| AMP 与显存 | autocast/scaler 路径及 CUDA 示例；显存实验脚本 | 全模型 fp16、任何设备均提速、任意大模型都能装下 | 做一组质量/峰值/时间对照，说明跳步与计时范围 |
| DDP | CPU gloo 实验、sampler/no_sync/归约与恢复测试 | 大规模多节点/NCCL 性能和所有不等长输入协议已验证 | 手画两 rank 窗口，解释通信顺序；目标硬件再做验证 |
| 断点续训 | [checkpoint.py](../../src/checkpoint.py) 恢复模型、optimizer、进度和 RNG；MLP 配对通过 | 任意 micro-step、multiworker、全 rank RNG、故障写入都支持 | 说明当前 epoch 级边界，做状态遗漏反证 |
| 数据与统计 | 固定切分、样本加权指标、可学习合成数据 | 真实任务泛化和稳定提升 | 留出集、多个 seed、错误分析；说明置信区间/标准差口径 |
| 测试与 CI | 回归、数值参照、流程和双平台 CI | CI 通过即生产可用 | 写能因关键逻辑删除而失败的判据，区分 mock 与硬件实测 |
| Diffusion/LoRA | [diffusion-lora-lab](https://github.com/colorHur/diffusion-lora-lab) 有训练、推理与服务脚本 | 文本 SFT、完整 LLM 后训练、质量已定量提升 | 讲出 latent/noise/timestep/conditioning，做独立 prompt 评测 |
| API 服务 | FastAPI 单/多 adapter 原型 | 多请求隔离、生产并发、零显存成本已证明 | 切 adapter 与整个生成统一隔离；测排队、异常恢复与成本 |
| RL/世界模型 | [world-model-lab](https://github.com/colorHur/world-model-lab) 提供研究与评测入口 | 已验证有效 Dreamer、机器人真机控制 | 先核对采样/边界语义与基线，再做闭环对照 |
| Linux/Docker/SQL | 可作为近期工程补强；本次不认定已有实战 | 文件/依赖里出现名字即熟练 | Linux 从零启动与查日志；一个可复现容器；独立写 JOIN/分组查询 |
| Transformer/LLM/RAG | 可复用张量、优化和评测基础，需另做任务 | 装了 transformers/PEFT 即完成 SFT/RAG | 手算 attention/mask；小型文本任务或引用问答基线 |

训练项目的边界依据当前源码；扩散项目已有流程可见，但并发隔离、尾更新语义与质量评测仍要升级。研究项目以具体版本与重跑结果为准，本表不宣布此前报告的问题已经修好。

## 3. 两周内抓哪些，之后怎样衔接

| 阶段 | 优先能力 | 最小可验收作品 |
|---|---|---|
| 当前七节课程 | Python/PyTorch、loss、优化、恢复、测试 | 手算和数值对照；一份错误定位报告；闭卷写最小训练循环 |
| 与课程同步 | Linux 基本操作、数据切分、基础算法 | Linux CPU 冒烟；固定评测协议；Python 独立写数组/哈希/双指针等练习 |
| 扩散项目深化 | Diffusion、LoRA、配置日志、质量评测、服务 | 可追踪训练配置；未见 prompt 集；单变量消融；请求隔离测试 |
| 有对应任务后 | Transformer/SFT、检索、SQL/Docker | 一个真实需求的闭环，保留基座/规则/检索等对照 |
| 有明确目标与算力后 | vLLM、FSDP/DeepSpeed、机器人/时序方向 | 在合适硬件与任务上验证机制、资源成本和结果 |

上述不是禁止接触其他技术，而是避免同时开很多无验收主线。C++/CUDA、K8s、ROS2 等按具体岗位要求和任务再决定，不由库热度决定。具身方向先区分视觉/数据、策略学习、仿真评测、机器人软件与真机控制，逐项核对自己已有证据。

## 4. 个人掌握程度的四级检查

| 等级 | 能做什么 | 合适的表述 |
|---|---|---|
| 0 | 看过名词但解释不清 | 学习中 |
| 1 | 能在提示下运行，知道输入输出 | 跑通过相关流程 |
| 2 | 闭卷解释机制和边界，完成最小实验 | 理解并能操作 |
| 3 | 换数据/损失/设备时独立修改并验证 | 能独立实现与调试指定场景 |
| 4 | 处理真实任务失败，量化取舍并交付 | 用具体结果描述工程经验 |

不要用测试数量给自己自动打 3/4 分。学习记录保留自己的解释、命令和结果，面试时展示其中最有证据的一项。对还没验证的路径直接说明条件，并给下一步验证方案。

## 5. 面试材料如何落到证据

训练项目可以讲“尾窗口更新次数正常却幅度偏小，构造参照后修正样本权重”；恢复可以讲“模型状态与随机流是不同对象，如何配对验证”；服务可以讲“共享 pipeline 状态为何需要覆盖整个生成过程的隔离”。每条描述链接到对应代码/测试/报告。

像素差说明输出变化，不等于质量提高；adapter 常驻内存与切换增量分开测；扩散 LoRA 不自动等于文本 SFT；小型 MLP 世界模型不自动等于成熟视觉世界模型。求职表达把任务、方法、结果与限制连在一起，面试追问才有稳定落点。

参考入口：[PyTorch Learn the Basics](https://docs.pytorch.org/tutorials/beginner/basics/intro.html)、[HF Diffusion Course](https://huggingface.co/learn/diffusion-course/en/unit1/1)、[FSDL 课程](https://fullstackdeeplearning.com/course/2022/)。学习顺序和技能评价规则是本课程设计，不是这些来源对个人能力的判断。
